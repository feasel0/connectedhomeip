1. `src/python_testing/matter_testing_infrastructure/matter/testing/spec_parsing.py`
   - Introduce `UnsupportedConstraintError`, a narrow `SpecParsingException` subtype emitted by `Constraints.require_supported()`. Existing callers catching the base exception remain compatible; unrelated parsing failures do not acquire the unsupported classification.
   - Parse explicit fields for directionless command overlays using the existing command-field parser. Inheritance retains derived overrides and unsupported-expression markers for accepted and generated commands without mutating base definitions.
   - OR the explicit-conformance marker across repeated command declarations, including access-only declarations, without changing the existing conformance OR operation or operand order.
   - Retain nested or nonnumeric `minLength`/`maxLength` XML as unsupported expressions. Simple numeric bounds continue to parse normally.
2. `src/python_testing/TC_IDM_9_1.py`
   - Catch only the narrow unsupported exception at each command-field probe boundary.
   - Report endpoint/name path, cluster ID/name, command ID/name, field ID/name, and the unsupported expression. Record strict-version errors and earlier-version warnings.
   - Continue independent fields after unsupported evaluation or transport failures. Unsupported cases never increment tested/probed/rejected accounting.
   - Keep harness evaluation failures distinct from DUT acceptance, DUT constraint rejection, transport/device failures, and other response statuses.
   - Fail incomplete strict 1.7 coverage explicitly after the loop. Preserve existing DUT-acceptance enforcement and earlier-version requirement to observe a real constraint rejection when supported probes run.
   - Do not catch ordinary `SpecParsingException` or programming errors such as `ValueError`.

No production change to `support_modules/idm_support.py` was necessary. No broad exception handling, generic result framework, runner, or discovery mechanism was introduced.
