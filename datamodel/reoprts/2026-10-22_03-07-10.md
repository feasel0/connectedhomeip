The narrow compatibility comparison found a real definition distinction, not merely an interchangeable historical spelling:

- Packaged 1.6 defines Wi-Fi security bits 0..4, not bit 5.
- Earlier provisional 1.7 names bit 5 WPA3-Matter-PDC and describes Per-Device Credentials.
- The approved current 1.7 reference names the same position IEEE8021X and explicitly includes Enterprise and Per-Device Credentials. Authorized read-only inspection of the pinned private source corroborates that definition; no private source text/configuration is reproduced here.
- Current SDK generated ZAP metadata retains the earlier enum spelling for wire value `0x20`. Keeping that identifier avoids a model/codegen dependency and does not itself settle older-release semantics.

**Decision:** the EAP mapping is correct for current 1.7 forward-development scan-result semantics and can be proposed independently. It is not proven universally compatible with every older advertised Matter definition. The Linux draft explicitly documents the older-definition distinction and requires release/backport owners to assess the applicable advertised-version contract before applying it to such products. That is a compatibility boundary for older-release use, not evidence for adding dynamic per-peer/version handling to this decoder. No runtime gating, generated enum rename, device version bump or new policy was invented. The two older artifact definitions do not prove runtime interoperability; no such claim is made. The SDK's top-level SPECIFICATION_VERSION file alone is not treated as runtime advertisement proof.
