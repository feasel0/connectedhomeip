# Linux EAP Second-Decoder Correction and PR Status

## Outcome

The reported bypass is real. Network Commissioning does not rely solely on
`WpaSupplicantClient::GetBssInfo`: its Linux driver initiates a scan through
`ConnectivityManagerImpl::StartWiFiScan`, whose scan-done callback uses
`ConnectivityManagerImpl::_GetBssInfo`. The latter discarded EAP membership.

The existing Linux [draft #74889](https://github.com/project-chip/connectedhomeip/pull/74889)
now fixes both production implementations. Its published head is
`3ced1ae3d9b8e3f82ac3a9c63b08056cbbae5cf9`, a normal forward commit from
`8d021c02a266803d165324a92e99c79f024c5fda`, pushed only to
`feasel0/connectedhomeip:datamodel/linux-eap-bitmap-20261022`.
This increment changes three files, with 78 insertions and eight deletions;
the complete PR now has five files. No additional SDK PR was created.

Accepted second-path negative control: **eight passed, four intended assertion
failures**. Corrected and final formatted executables: **twelve passed**.
These are actual production decoder and generated-struct TLV tests, not live
D-Bus acquisition, hardware testing, a full SDK build or hosted-CI acceptance.

## Production Routing and Build Configuration

The inspected Network Commissioning route is:

1. `NetworkCommissioningCluster::HandleScanNetworks` calls the selected Wi-Fi
   driver's `ScanNetworks`.
2. `LinuxWiFiDriver::ScanNetworks` calls `ConnectivityMgrImpl().StartWiFiScan`.
3. `StartWiFiScan` sets the one-shot callback and requests a D-Bus scan.
4. `_OnWpaInterfaceProxyReady` registers the manager's `scan-done` handler.
5. `_OnWpaInterfaceScanDone` calls the manager's `_GetBssInfo` for each BSS,
   collects the results and dispatches `OnScanFinished`.
6. `OnScanFinished` invokes the stored callback. The cluster's Wi-Fi
   `OnFinished` uses `WifiScanResponseToTLV`, which directly copies
   `scanResponse.security` into `WiFiInterfaceScanResultStruct` and invokes
   `DataModel::Encode`.

The separate `WpaSupplicantClient` path remains present:
`ConnectivityManagerImpl::_Init` calls `WpaSupplicantClient::Init`; the client's
`OnWpaInterfaceProxyReady` independently registers its `scan-done` handler;
`OnWpaInterfaceScanDone` calls `GetBssInfo` and forwards through the same manager
`OnScanFinished`. `ScanNetwork` is the client's scan-request entry point.
No claim is made that Network Commissioning calls that entry point: the driver
explicitly calls `StartWiFiScan` instead. Neither decoder is assumed to replace
the other.

The Linux GN target includes the network-management source when Ethernet or
Wi-Fi is enabled and `chip_linux_network_manager == "wpa_supplicant"`.
Other network-manager selections currently assert unsupported. The Wi-Fi driver
is added when Wi-Fi is enabled. The optional Wi-Fi PAF manager separately
selects its source; when either manager needs wpa_supplicant, the target includes
the client and exports the generated D-Bus dependency. The manager implementation
and its private seam are guarded by `CHIP_DEVICE_CONFIG_ENABLE_WPA`.

The executable proof uses the configured Linux Wi-Fi/wpa_supplicant build.
Other GN configurations were inspected, not independently built. No dynamic
manager-selection, PAF behavior or test-registration change was made.
