## Assessment and Correction

The reported inherited-response concern was real, but the existing direct-response behavior matters. Direct fabric-scoped responses already retained `fabricScoped` access metadata and retained `timed` when both flags were present. Direct timed-only responses emitted no access element. The old inherited timed-only response incorrectly emitted access because the outer decision still used the unresolved direction.

Blindly suppressing all response access would change the existing fabric-scoped behavior. Instead, the correction consolidates the direct-response access block into the shared renderer, resolves direction once, suppresses response invoke privileges, and uses that resolved direction for timed-only access eligibility. Fabric-scoped response metadata remains unchanged. Direct and inherited responses now agree without mutating the overlay direction or inventing an XML direction attribute for an inherited overlay.

The assertion now uses comma-ok and a nil check. This is a small defensive guard, not a demonstrated existing panic repair: the current `CommandSet` is typed as `[]*Command`, and its `Identifier` implementation currently returns a matched command. A nil entry would already dereference inside that lookup, so the caller guard is not claimed to repair that separate condition. No lookup redesign or synthetic impossible wrong-type fixture was added.
