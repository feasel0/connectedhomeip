## E. Authorization And Availability

The root cause is the shared `ModeBase::Commands = ThermostatMode::Commands` alias. Unconditionally returning its generated entries promotes ordinary ModeBase commands to Manage after #74803. The correction selects the generated Thermostat entry by actual cluster identity instead of weakening Thermostat's metadata or changing global authorization.

Current generated ChangeToMode metadata for all nine ordinary command-bearing aliases independently declares Operate and empty command-quality flags. The explicit ordinary entry matches those definitions. MicrowaveOvenMode has no ChangeToMode command. Both Thermostat accepted entries still consume the unchanged generated Manage metadata; there is no duplicate metadata override.

The native matrix exercises **264 encoded invocations**: eleven aliases, COREMODES off/on, ChangeToMode/core-tag/valid-unimplemented command `0x7F`, and four distinct View/Operate/Manage/Administer CASE subjects. Native ACL entries explicitly bind each subject to its granted privilege on fabric 1; no administrator-credential assumption grants lesser subjects access. Candidate outcomes are 90 successful command responses, 69 UnsupportedAccess statuses and 105 UnsupportedCommand statuses. Success includes observed delegate execution/current mode 1; rejection includes unchanged mode 0 and untouched delegate markers.

Of these, 144 invocations use configurations admitted by the inspected codegen integration: ordinary aliases without COREMODES and Thermostat with COREMODES off/on. The other 120 deliberately exercise ordinary COREMODES configurations through direct cluster construction as synthetic robustness controls. They are not advertised as available through codegen registration. This distinction also applies to the existing ordinary COREMODES unit controls.

Source inspection confirms the supported wiring: ModeBase Instance::Init validates the aliased cluster/features and registers its real server cluster; CodegenDataModelProvider::AcceptedCommands obtains metadata from that registry; its InvokeCommand routes to the same registered cluster. InteractionModelEngine uses that entry's invoke privilege in real AccessControl::Check. CommandHandlerImpl rejects failed validation before invoking dispatch. Thus the edited owning metadata controls authorization on this path, rather than a test-only comparison helper. Full codegen-registration execution remains unverified locally, as stated above.

The production change leaves both existing availability conditions intact: Microwave exclusion for ChangeToMode and COREMODES admission for the core-tag command. It does not alter unknown-command handling, command IDs, command flags, response types, other clusters' authorization machinery, delegates, public APIs or generated files. Unsupported commands remain unavailable even to Manage/Administer subjects.
