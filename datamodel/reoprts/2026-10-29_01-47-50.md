## 3. Mechanism and Exact Correction

`ReadClient::ProcessReportData` invokes final `OnReportEnd` before waiting for a future SubscribeResponse. `ProcessSubscribeResponse` later invokes `OnSubscriptionEstablished`. Darwin report-end delivery traverses asynchronous device/delegate queues and could release the old setup expectation while state 1, Subscribing, was still correct. Draining queues orders already-enqueued work, not a future network response. The state writer and `_getInternalState` share locking; the defect is an expectation for the wrong event, not an established unsynchronized state read.

Exactly one existing file changes: [MTRDeviceTests.m at the qualified source head](https://github.com/project-chip/connectedhomeip/blob/1f64cd2e1de5b129dcae3ad182113f725af77287/src/darwin/Framework/CHIPTests/MTRDeviceTests.m), **+3/-12**. Only the initial expectation setup is replaced in:

- `test048c_MTRDeviceSubscriptionPoolSlotReleasedAfterInvalidate`.
- `test048e_MTRDeviceSubscriptionPoolSlotOfNewerWorkKeptWhenResubscriptionWorkRunsLate`.
- `test048i_MTRDeviceSubscriptionPoolSlotReleasedAfterInvalidateTearsDownReadClientLate`.

Each now uses existing `_expectationForSubscriptionEstablishedOfDevice:delegate:queue:description:onEstablished:` with `onEstablished:nil`, installed before `setDelegate`. That helper receives `onInternalStateChanged`, reads the locked state, ignores nonestablished states, clears its callback and fulfills only for initial/later established states 2/4. The following unchanged strict assertion still requires **initial state 2**; accepting 4 in the existing helper does not weaken that assertion. The neighboring `_subscribedDeviceWithNodeID:controller:delegate:queue:` already follows this establishment-based pattern.

Every other byte of the file is preserved: 60-second waits, queue drains, delegate/Thread configuration, test048e's 20-second interval override, pool counts, blocked queues, late resubscription, invalidation and late ReadClient teardown assertions. No sleep or timeout increase, state-1 acceptance, assertion removal, production subscription change, polling, sanitizer suppression or CI/compiler/protection change was introduced. The preexisting test048e reachability-aging sleep is unchanged, not the correction.
