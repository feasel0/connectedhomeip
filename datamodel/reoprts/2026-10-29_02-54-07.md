## Defect And Behavioral Review

The original helper converts raw LONG_DISCRIMINATOR input into a manual pairing code. Manual codes preserve only the upper four discriminator bits. Long values 3840 and 4021 therefore share short bucket 15; matching the manual payload admits both. The new QR payload retains the complete 12-bit discriminator and excludes the other device in both directions.

Only `setup_code is None` plus LONG_DISCRIMINATOR takes the QR branch. Discriminators outside 0..4095 are rejected before native narrowing or a fatal setter. The existing native payload API retains passcode validation and explicit unspecified VID/PID 0/0.

Supplied QR/manual strings, including lowercase/empty strings and inconsistent raw metadata, bypass generation unchanged. Raw SHORT still calls the same manual-code API with the original arguments. The PASE call, timeout/error propagation, retry behavior, missing MeshCoP host/port rejection and valid MeshCoP host/port forwarding remain unchanged.

Capabilities 0x3F represent exactly SoftAP, BLE, OnNetwork, WiFiPAF, NFC and Thread. The real compiled pairer predicate admits all six for both manual and generated QR payloads. Connect dispatches BLE, WiFiPAF, NFC and Thread; DNS-SD discovery remains unconditional. SoftAP is recognized but has no Connect dispatch. `kNone` is a zero sentinel, not a discovery channel. Reserved bits 0x40/0x80 have neither enum channels nor Connect dispatch. The predicate difference for the zero sentinel and reserved bits is tested and is not described as universal bit-pattern equivalence.

Production call-site review confirms DNS-SD builds a long-discriminator filter from a full-width payload and BLE receives the payload discriminator. The private probe tests actual predicate logic, not physical discovery or commissioning. No speculative refactor or missed within-scope defect was established.
