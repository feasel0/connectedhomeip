## Actual Advertised And Parsing Contracts

- `src/app/SpecificationDefinedRevisions.h` declares `Revision::kSpecificationVersion = 0x01070000`; Basic Information's `PolicyBased.h` encodes that value for SpecificationVersion. The root SPECIFICATION_VERSION file says 1.2.0 but is not this runtime attribute's owner.
- Generated `clusters/NetworkCommissioning/Metadata.h` declares `kRevision = 3`; `NetworkCommissioningCluster::ReadAttribute` encodes that value. Codegen integration registers this code-driven cluster. The XML also declares revision 3.
- The runtime therefore agrees numerically with the declared in-progress development target. However, earlier provisional definitions can share these version/revision identifiers; those numbers alone cannot distinguish the two bit-5 meanings.
- Both decoders accept exact case-insensitive strings. Recognized EAP becomes the internal bit-7 sentinel, then `kWpa3MatterPdc = 0x20`; bit 7 is cleared. Neither decoder gates that conversion on SpecificationVersion, cluster revision, or the device's PDC feature setting.
- PDC feature advertisement is separately conditional on `CHIP_DEVICE_CONFIG_ENABLE_WIFI_PDC` and driver capability. Generic scan classification does not establish that feature or PDC credential compatibility. The default configuration disables that feature.
- Production route: `LinuxWiFiDriver::ScanNetworks` -> `ConnectivityManagerImpl::StartWiFiScan` -> registered scan-done handler -> `_GetBssInfo` -> callback -> `WifiScanResponseToTLV`. The serializer copies the security bitmap into the generated result struct unchanged. The separate `WpaSupplicantClient::GetBssInfo` decoder is independently exercised.
- Generated scan-result structs carry a bitmap8 at context tag 0. No selected-version field or conditional reinterpretation is added by the generated encoding/decoding path. The probe verifies the actual generated TLV round trip, not a handwritten classifier.
- A targeted search of `src/lib/dnssd` found no use of WiFiSecurityBitmap, kWpa3MatterPdc or IEEE8021X. DNS-SD does not repair or disambiguate these scan-result bits. This is a bounded source finding, not a claim about every external controller.
- No physical Wi-Fi scan, live D-Bus service, legacy controller exchange, UI selection error, or released-product interoperability failure was executed. Current-target correctness and contingent older-contract risk must not be conflated.

## Preferred Decision And Alternatives

Preferred: retain generic-EAP classification for the explicitly declared current in-progress IEEE8021X contract; do not remove it merely because generated identifiers retain the older PDC spelling. Obtain an explicit applicability decision for the stale schema and older products before any corrective publication. Then qualify the canonical Suite-B parser addition against that selected contract in both production paths.

Alternative: align generated schema and public names with the current authoritative definition in a separately authorized model update. This changes a shared/public model surface and is outside an automatic parser correction.

Alternative: require a legacy-product policy for unsupported enterprise networks under the PDC-only/no-bit-5 contract. Filtering, failure behavior, or alternative representation needs explicit contract selection. A bare 1.7/revision-3 runtime gate cannot distinguish the provisional definitions and is not justified by this investigation. Do not invent a reserved bit or equate Suite-B-192 with WPA3-Personal/PDC.
