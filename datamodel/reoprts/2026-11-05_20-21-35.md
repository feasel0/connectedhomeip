## Findings

### Medium: Preexisting IDM Verdict Can Pass Without Enforcement Evidence

In #75140's actual captured helper, `ConstraintProbeResult.probed` includes
`other_error`. The command checker records INVALID_COMMAND and RESOURCE_EXHAUSTED
as warnings, with zero accepted and zero rejected violations. The TC counts these
as exercised probes. Its strict-version policy then returns successfully whenever
`accepted_paths` is empty, without checking `rejected_count` against the probes.

References, pinned to 3d322af4ea0c2684d13586767dc3388fb77f8300:
- [Probe accounting](https://github.com/project-chip/connectedhomeip/blob/3d322af4ea0c2684d13586767dc3388fb77f8300/src/python_testing/support_modules/idm_support.py#L75).
- [Strict policy](https://github.com/project-chip/connectedhomeip/blob/3d322af4ea0c2684d13586767dc3388fb77f8300/src/python_testing/support_modules/idm_support.py#L1054).
- [Unrelated-status path](https://github.com/project-chip/connectedhomeip/blob/3d322af4ea0c2684d13586767dc3388fb77f8300/src/python_testing/support_modules/idm_support.py#L1593).
- [TC aggregates and enforces](https://github.com/project-chip/connectedhomeip/blob/3d322af4ea0c2684d13586767dc3388fb77f8300/src/python_testing/TC_IDM_9_1.py#L114).

A new private seven-case probe executed the captured real TC/helper with its
existing test fixture and mocked transport. In strict mode, INVALID_COMMAND and
RESOURCE_EXHAUSTED ordinary-only runs passed with one request and zero constraint
rejections. A mixed diagnostic/ordinary INVALID_COMMAND run also passed with zero
constraint rejections. Controls: strict CONSTRAINT_ERROR passed; strict acceptance
failed; earlier-version INVALID_COMMAND failed; earlier-version CONSTRAINT_ERROR
passed. No hardware enforcement or new hosted execution is implied.

This is a reproduced preexisting policy gap, not a regression introduced by the
diagnostic exclusion or the merged numeric-generator change. #75140 correctly
prevents diagnostic EnableKey rejection from being credited to Count, and its
all-diagnostic case remains SKIP. It does not close this ordinary-command gap.
Recommend a separate explicit verdict-policy follow-up and whole-TC regressions
for unrelated statuses. Until then, a TC PASS is not proof that every exercised
ordinary constraint returned CONSTRAINT_ERROR. Do not describe #75140 as complete
constraint-enforcement qualification.

## Residual Risks And Limits

Push AV #75139 allocates `2 * input length` scratch before the delegate's product
size cap, then sorts IDs. Large early-duplicate input can use more memory and work
than the old prefix-based set. Null scratch falls back to the prior set, preserving
the earlier node-allocation exhaustion contract rather than proving universal OOM
safety. These are real disclosed tradeoffs, not newly discovered regressions.
[Allocation](https://github.com/project-chip/connectedhomeip/blob/e0b26402bfb4642b63d7dc7040c8a7e7d60b15e5/src/app/clusters/push-av-stream-transport-server/PushAVStreamTransportLogic.cpp#L909)
precedes the
[product cap](https://github.com/project-chip/connectedhomeip/blob/e0b26402bfb4642b63d7dc7040c8a7e7d60b15e5/src/app/clusters/push-av-stream-transport-server/PushAVStreamTransportLogic.cpp#L960).
Duplicate checks and sorting only change scratch, not stored input order. Late
Ambient sensitivity checks follow duplicate/decode/size/ZoneID validation.

The full #75139 PR includes #74979, so its eight-file diff is not an isolated
resource-only patch. After prerequisite merge, re-evaluate the resulting comparison
and ordinary integration; do not promise that inherited files disappear unchanged
without checking. The Closure Dimension trio also touches the same owner/private
validation helper. Existing disposable combined tests support compatibility, but
ordinary merge resolution and final-tree gates still matter.

The preceding campaign qualified unchanged #75139/#75140/#75138 heads: each had
39/39 technical definitions and current bot closure. Retained local evidence:
Push AV 19 native/19 sanitizer, 560 ordering/1680 fault/868 sensitivity cases;
IDM 42 combined plus five PIXIT methods and both native TC run variants; Step
65 native/65 sanitizer, combined compatibility 70/71/76. Push AV's separately
registered matching ESP32 QEMU image passed all 74 methods with published source
and actual image/binary/archive freshness proof. This is retained prior evidence,
not a rerun in this review, physical-device qualification, full stack/WCET bound,
or immunity to regressions. The new private policy probe is the only fresh behavior
execution in this review. No live specification requalification was performed;
the EAP judgment is conditional on its explicitly declared current contract.

Overall: most changes are tight and low risk in their stated scopes. I found no
additional regression in the modified runtime paths. I would not label all eleven
uncontroversial or guarantee no negative effects. Prioritize the test-policy gap,
current descriptions and explicit EAP/resource boundaries over another general CI
rerun. Passing bots and CI are supporting evidence, not a zero-risk argument.

### #75139

#### Problem

Motion-zone duplicate validation allocates one set node per unique ID. It also
needs the same validation and owning-storage behavior across Allocate/Modify and
Motion/AmbientContext.

#### Solution

Use checked input-sized uint16_t scratch and sort to detect duplicates, falling
back to the existing set validator if scratch allocation fails. Preserve error
precedence, delegate order and accepted storage order. Validate Ambient per-zone
sensitivity against the enabled feature.

Depends on #74979 and includes its changes. Scratch is allocated before the
product-size cap; early duplicates can use more memory than the previous validator.
Fallback preserves the existing node-allocation contract, not universal OOM safety.

#### Testing

- 19 native and 19 ASan/UBSan/leak-check methods pass, covering ordering,
  allocation failures, sensitivity and owning-storage reload. For 128 unique IDs,
  normal scratch requests 256 bytes instead of 4096 bytes across 128 set nodes;
  constrained-block controls exercise fallback.
- Current-head technical CI passes 39/39 workflows. Actual Linux/nRF execution
  and the targeted ESP32 QEMU image pass; the image executes all 74 methods.
  No physical-device or full task-stack qualification is claimed.

### #75140

#### Problem

A generated diagnostic EnableKey can cause rejection independently of the field
under test, falsely crediting constraint enforcement such as PayloadTestRequest.Count.

#### Solution

Exclude GeneralDiagnostics.TestEventTrigger and PayloadTestRequest at the invocation
boundary. Keep constrained fields discoverable and report their paths and reasons
as NOT DEMONSTRATED; never synthesize a key, trigger or cleanup operation.

Run remaining command and writable-attribute checks under the existing policy.
All-excluded command scope is unsupported/SKIP, not PASS; ordinary failures retain
precedence. Diagnostic coverage and existing unrelated-status verdict handling
remain outside this correction. The merged #74959 numeric behavior is unchanged.

#### Testing

- 42 combined unit methods and five PIXIT neighbors pass, including no-call,
  exclusion/accounting mutations and failure-precedence controls.
- Current-head technical CI passes 39/39 workflows and both native TC-IDM-9.1
  run variants execute. Offline controls use mocked transport; no physical-DUT
  diagnostic enforcement is claimed.

### #75138

#### Problem

Step/GroupedStep can invoke the delegate before rejecting a computed target.
With Resolution=3 and position=9999, an increase can clamp to off-grid 10000,
produce a delegate effect, then return Failure.

#### Solution

Validate the complete candidate before invoking the delegate, reusing unchanged
setter checks. Preserve Failure, accepted delegate arguments and publication only
after delegate success. The endpoint-clamping policy remains out of scope; this
example still fails, but without delegate effects, state changes or reports.

Independent of #75000 and #75019; no public API or heap allocation is added.

#### Testing

- 65 native and 65 ASan/UBSan/leak-check methods pass. Both new regressions fail
  on the original implementation; rejection leaves delegates, state and reports untouched.
- Disposable compatibility with both related PRs passes 76 methods; current-head
  technical CI passes 39/39 workflows. No live groupcast or motor testing is claimed.
