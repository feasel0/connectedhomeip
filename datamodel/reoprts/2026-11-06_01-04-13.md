## Live Description: #75139

### Problem

MotionZones duplicate validation allocates one `std::set` node per distinct zone before applying the product's list-size limit, increasing heap allocation and fragmentation on embedded targets.

### Solution

Use a checked, input-sized `uint16_t` scratch buffer and sort it to detect duplicates. If scratch allocation fails, fall back to the existing `std::set` validator.

Preserve duplicate/error precedence, delegate behavior, accepted zone ordering and persisted data.

**Dependency:** #74979 supplies the shared MotionZones validator, AmbientContext validation and owning storage. This PR changes duplicate tracking without changing those contracts.

### Migration Status

The sensitivity pass is present in #74979 and integrated here, but migration qualification is blocked by the parent's persistence-API/test-fixture integration. This stack is not fully qualified.

### Testing

- 19 native and 19 sanitized tests pass, including allocation-failure, duplicate-ordering, malformed-input and persistence regressions.
- Current-head targeted ESP32 QEMU did not execute; the parent fixture build stopped before runtime.
- New-head hosted CI and automated-review qualification are incomplete; parent CI has an actual compile failure.

### Limitations

Scratch allocation is bounded by input length, not the product's zone limit. Fallback preserves the existing node-allocation behavior and does not guarantee recovery from total heap exhaustion.

The change does not establish universal device-level heap, stack or worst-case timing bounds.
