## Native Read Dependency

[SDK #75201](https://github.com/project-chip/connectedhomeip/pull/75201) remains at `ac626464eb02a374ecf182b170d0b6b864e4ac74`. Its native-read review thread remains open. No unsafe Future cancellation, arbitrary abandonment timeout, or published controller cancellation change was introduced.

Actual ownership was traced through pychip_ReadClient_Read, ReadClientCallback, AsyncReadTransaction, controller Read/ReadAttribute, ReadClient and ExchangeContext. Native startup transfers ownership to the callback, explicitly retains the Python transaction, and completes through OnDone. Python OnDone clears the pointer, settles the Future and releases that explicit reference. The exported ShutdownSubscription deliberately aborts the process for a one-shot read; ReadClient::Close is private. Each non-final report resets the exchange response interval, so continuous chunks do not provide an overall deadline.

A narrow additive dependency is prepared in private detached commit `2a9d9c5e319d66e247e5b6d53a5ea3ddd6ca1498`, parent ac626, with four SDK files and a patch/contract handoff. It is not pushed and is not a published strict-probe repair. It routes a one-shot AbortRead through Close/OnError/OnDone, rejects subscriptions unchanged, treats an already-cleared pointer as a no-op, reads that pointer on the CHIP thread, and installs it on that thread before completion can clear it.

Seven actual-controller controls passed normally and with the fresh native owners and private report probe under ASan/UBSan:

1. Normal wire read and late idempotent abort.
2. Real delayed response with the owned software DUT paused/resumed.
3. Eight actual native non-final reports keep the read pending beyond two 250 ms response intervals; a final report settles it.
4. Repeated outer cancellation remains pending until explicit native abort, preserves the first CancelledError identity, and never cancels the callback-owned Future. Safe cleanup then restores and reads back the actual baseline through the same settlement helper; no later violating probe starts.
5. A real deliberately misaddressed cleanup write returns UnsupportedEndpoint; cleanup diagnostics remain separate and original cancellation remains primary, with no later read probe.
6. A stopped chunk stream produces native timeout, clears the pointer and settles once.
7. A subscription is rejected by one-shot abort without mutation, then settles once through normal Shutdown.

The exact published nested settlement helper was extracted for these native controls, not replaced with mocked coroutines. Each control observed one OnDone and no Future cancellation. The native libraries, source/helper hashes and owned fixture receipts are preserved in isolated campaign evidence.

Important limits: non-final reports were injected into the actual native exchange, not sent by a hostile DUT over the wire; test-only MRP flags permitted controlled injection. Only the two owning objects and probe were instrumented, remaining matched dependencies were uninstrumented, and Python leak detection was disabled. This is not whole-SDK sanitizer/leak coverage or proof of a finished public abort/deadline contract.

Before publication, this dependency needs retained SDK unit tests, a supported controller handle with explicit opt-in cancellation/overall-deadline semantics, and its IDM consumer. Startup/completion races, repeated cancellation, abort failure, restoration budgets and hostile over-the-wire chunking remain gates.
