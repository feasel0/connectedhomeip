An outgoing grouped ECRED request lists its initiating channel first, then
deferred channels. Response handling currently assigns DCIDs in connection
list order instead of request order. With a non-first initiating channel,
this associates the wrong remote bearer and can stop ATT discovery or
subscription setup. A correctly ordered peer response is sufficient.
The grouped channels must satisfy the existing same-PID/PSM and pending
ECRED-mode filters; no hostile peer input is needed for the observed fault.

Fix the requester by retaining each SCID's request-array position in its
channel and using that position for response lookup. Validate that slot's
length, reject repeated positions and require an outgoing request pending.
Do not shift later assignments when a pending channel disappears.
The change adds one byte field to the internal channel structure; no
userspace structure or wire format is changed. Structure-layout consumers
must be rebuilt together. No unmeasured size or performance claim is made.
