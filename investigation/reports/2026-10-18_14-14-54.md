### SDK Scope And Harness Judgment

**Retain the production changes and native harnesses; no code simplification
needed in this pass.** Native scanner stop failure now releases local Linux
state and reports an error rather than success. Startup errors retain precedence
over cleanup errors. BLE connection cancellation is made inactive before its
stop callback; normal scan errors still preserve the application callback
context. Python's uint32 callback matches the native error width, bounds queue
waiting, retains captured results, and cleans early-close/start-failure paths.
Darwin teardown serializes with callbacks, cancels the timer, detaches the
delegate, clears Python state and guards late work. Initial unavailable states
cannot stop a not-yet-activated timer because initialization suspends the queue.

The Linux fixture is a small private D-Bus service with only the adapter/control
surface needed for start/stop failures; it does not use or reset a real adapter.
The timer interposer is a test-only GN target, not a production failure hook.
The Darwin harness substitutes CoreBluetooth construction while including the
actual scanner implementation. Its deterministic queue probe tests in-flight
deletion, same-queue deletion, late work, timer expiry and unavailable initial
states. Those are distinct native regression boundaries which Python mocks
cannot establish; their maintenance cost is warranted by the lifetime risk.
