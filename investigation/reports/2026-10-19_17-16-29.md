## Decisive Enhanced-ATT Sequence

The installed `tshark` version does not fully decode enhanced-channel ATT.
Its apparent absence of characteristic discovery is not reliable. Independent
`btmon` decoding exposes the following operations, including a05's actual
characteristic request and response. No Find Information descriptor discovery
appears in these five captures in the independent decode.

Every failing attempt negotiates the same ordered pair:

1. DUT sends Enhanced Credit Connection Request 0x17, PSM 0x0027, source CIDs
   `[0x0041, 0x0040]`.
2. Controller accepts with response 0x18, result success, destination CIDs
   `[0x0040, 0x0041]`.
3. These pairs map controller local 0x0040 to DUT local 0x0041, and controller
   local 0x0041 to DUT local 0x0040.
4. Controller sends discovery to DUT CID 0x0040 on the second bearer. Its
   response should arrive at controller local CID 0x0041, but arrives at
   controller local CID 0x0040 on the first bearer instead.
5. Controller immediately sends a channel Disconnection Request, before the
   subsequent native service error. Reverse requests/responses on other
   channels are separately visible. There is no earlier outgoing Read By Type
   request on the receiving bearer's corresponding TX CID to explain the reply.

## One Deciding Experiment, Not Launched

Remaining question: which peer's daemon/kernel maps the ordered enhanced-CID
list to sockets incorrectly, and does that abort BlueZ discovery before its
ServicesResolved/database export callback? The response sequence is observed;
exact responsible source and discovery-completion state are not.

One primary BLE-Wi-Fi smoke is justified only after the unchanged disk and
fixture gates pass. Keep the pinned native library, original multi-bearer
configuration and actual DUT app. Retain both peers' bounded HCI, BlueZ
discovery/debug events and EATT socket/CID mapping, D-Bus Device1/ObjectManager
event ordering, and a diagnostic native lookup snapshot of paths, UUIDs and
owning-device/service references. Exclude characteristic Value properties and
key/credential/storage data. Start observers before connection and retain
through lookup and teardown. Correlate one request/reply bearer and the database
completion status, not just ServicesResolved=true. Do not pre-emptively switch
to one channel, clear caches or add retries that erase the deciding state.

If the single smoke succeeds, it does not attribute or close the historical
failures. A prospective correction needs established peer implementation,
observed failure reproduction or equivalent causal proof, and matched
validation with the same observability. No broad matrix or new capture-system
project is needed. Current available disk is 6,810,546,176 bytes, below the
8,589,934,592-byte reserve, so no hardware operation was launched.
