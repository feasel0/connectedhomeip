## Minimal Correction and Lifecycle

An initial request-list-order-only candidate passed ordinary ordering controls
but failed the deciding pending-teardown case: remove the first pending channel
before its response and the survivor consumes the removed channel's DCID.
The pinned `l2cap_chan_close()` permits deletion in `BT_CONNECT`. That candidate
was rejected and is not the retained proposal; simple reversal is also invalid.

The retained patch adds `__u8 ecred_tx_index` beside `ident`, records zero for
the triggering channel and the actual emitted position for each grouped sibling,
then indexes `rsp->dcid` independently for each matching outgoing channel.
Response bounds use the original array length, not a shrinking traversal count.
A request-sent flag check excludes non-outgoing or security-retry-cleared entries.
Wire order and identifiers are unchanged. No allocation, list movement, channel
pointer array, transport change, delay or SDK workaround is introduced.

Both request-construction paths overwrite the index on every emitted request.
Removed entries cannot shift survivors' positions. Reused channel/CID storage
cannot retain an old position into a newly emitted request. Existing PID/PSM,
identifier, mode, state and deferred grouping filters remain intact. Security
policy and duplicate-CID disposal remain unchanged. Full kernel compilation,
struct-layout impact, concurrency, identifier-wrap behavior and live socket
lifetime are not proven by these host stubs and remain review/physical gates.
