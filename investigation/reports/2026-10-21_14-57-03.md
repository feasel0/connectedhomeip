### Bounded Retry Contract

Current multi-fix source was pinned to
`557b58b0f72ea23c969c2e5aeefe61d744fdf63a`. OnResponderBusy grants exactly
one exhausted-budget extra attempt, repairs a zero resolver budget, and has
a one-time guard under `CHIP_DEVICE_CONFIG_ENABLE_AUTOMATIC_CASE_RETRIES`.
OnSessionEstablishmentError first tries another resolver result, then needs
remaining budget to schedule a delayed attempt. LookupPeerAddress decrements
attempt/resolver budgets. CASESessionManager's public default attemptCount
is 1 when automatic retries are enabled.

The existing Busy regression source has four cases: grant after exhaustion;
preserve nonzero resolver budget; no grant while budget remains; no second
exhausted-budget grant. These were inspected, not compiled or executed here.
They document a bounded recovery contract, not July's binary/flags, initial
budget, timer behavior, remote availability, or guaranteed eventual success.
No speculative retry increase or CASE concurrency change is justified.

## Track C: Filter and Payload Controls

The existing discovery-isolation tool's 14 offline self-tests pass. The
known Nordic 3840 and Pi enhanced-window 4021 share short value 15 but differ
as long values. SDK SetupDiscriminator::MatchesLongDiscriminator compares
all bits for long matching and high bits for short matching. Pairer DNS-SD
selects filter width from parsed payload; multiple setup payloads instead
take a no-filter path, so the single-payload result is not generalized.

The inspected Python commissioning helper retains supplied QR setup strings.
Explicit CLI discriminator input can leave setup_code absent, after which
the PASE helper calls CreateManualCode. Nominal long CLI filter metadata
therefore does not establish the effective setup-code discovery filter.
This source inspection is not proof of every historical installed package.

No physical QR comparison was run. Any next comparison needs the actual
current-window QR, executed helper/filter width, and selected peer, with
reset/readiness and other advertisers controlled. QR neither disables DNS-SD
nor guarantees unique identity, advertiser authentication, or resolution of
later operational CASE failures.
