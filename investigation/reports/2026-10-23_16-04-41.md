## Current upstream defect and API boundary

Source inspection confirms the defect remains. In
`matter/testing/commissioning.py`, `get_setup_payload_info_config` records numeric
input as LONG with `setup_code=None`. `Commission._find_or_establish_pase_if_needed`
then calls `CreateManualCode(filter_value, passcode)`. A manual code retains only
the high four discriminator bits: 3840 (`0xF00`) and 4021 (`0xFB5`) both become
SHORT 15. Supplied QR/manual strings are retained instead.

`SetupPayload.GenerateQrCode` can retain the full discriminator, but defaults to
capabilities 4 and test VID/PID values. These defaults are not neutral metadata.
`PayloadContents::isValidQRCodePayload` requires rendezvous information to be
present; QR cannot encode the absent/unknown state used by a manual payload.

`FindOrEstablishPASESession` accepts a setup string and optional MeshCoP host/port;
it reuses an existing commissionee before establishing PASE. Its generic native
binding passes only the string to `EstablishPASEConnection`. `SetUpCodePairer`
parses that string into payloads. No structured-payload/full-discriminator input
is exposed along this Python-to-pairer path. Separate BLE/IP establish methods
do not preserve its general discovery and reuse behavior.

## Alternatives and compatibility

| Approach | Precision | Material problem |
| --- | --- | --- |
| Keep manual generation | Lost | Existing defect remains. |
| QR with default capabilities 4 | Retained | Disables BLE, Wi-Fi PAF, NFC and Thread eligibility in `ShouldDiscoverUsing`. |
| QR with all recognized bits, `0x3f` | Retained | Declares six capabilities instead of retaining unknown capabilities. |
| QR with a method-derived mask | Retained | Changes fallback eligibility; the network being provisioned does not uniquely identify the PASE discovery transport. |
| Direct on-network/BLE establishment | Retained where supported | Narrows transport behavior or bypasses the existing generic reuse path. |
| Add a structured-payload native/Python path | Retained | Can preserve absent rendezvous metadata, but adds an API path and exceeds a helper-only substitution. |

`ShouldDiscoverUsing` returns true for absent rendezvous information and otherwise
tests the requested bit. Consequently, `0x3f` matches its current recognized
channel predicates; that observation does not establish that synthetic declared
support is the intended contract. `Connect` always attempts DNS-SD, while BLE,
Wi-Fi PAF, NFC and Thread are conditionally eligible. Full precision also allows
PAF/NFC to pass their separate LONG-only checks; this is another reason not to
equate predicate coverage with complete transport equivalence.

Preferred semantics-preserving direction: separately authorize an additive
structured-payload path retaining a long discriminator and absent rendezvous
metadata. Alternatively, an owner could explicitly define a synthetic QR mask as
local discovery policy, with unspecified VID/PID and complete validation. That
policy is not established here. No low-risk, fully tested helper-only correction
is claimed under the current constraints.
