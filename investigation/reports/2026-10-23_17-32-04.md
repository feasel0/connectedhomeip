### Capability Semantics and Limits

The actual compiled SetUpCodePairer predicate preserves eligibility for SoftAP,
BLE, OnNetwork, WiFiPAF, NFC and Thread for both parsed manual and synthetic QR
payloads. Native encoding/parsing and enum-completeness checks accompany this;
the evidence is not merely a capabilities==0x3f assertion. Connect's real
mapping was inspected: DNS-SD is unconditional; BLE/PAF/NFC/Thread have their
corresponding dispatches. SoftAP is recognized but has no Connect dispatch.

The concurrent assessment in [the capability stop-gate report](2026-10-23_16-04-41.md)
correctly distinguishes absent rendezvous metadata from explicitly declared
capabilities. The new tests establish current recognized-channel eligibility,
not equality of those metadata states. kNone and reserved bits 6/7 differ:
manual absent metadata returns true, synthetic QR returns false. None is a
current discovery channel; these differences are explicitly tested. QR produce
validation rejects reserved bits, while consume validation accepts them.

Full LONG precision also enables LONG-only PAF/NFC checks that a generated
short manual code could not satisfy. This is not a claim of unchanged complete
transport behavior, nor proof of every backend's connection/fallback behavior.
No recognized channel predicate was restricted in the executed controls. The
draft PR exposes this scoped correction and its tests; it is not ready-for-review
or hardware-equivalence certification. An additive structured-payload API was
not introduced or treated as implicitly authorized.

Both native configurations freshly compiled 417 sources with at most two jobs,
using SDK Clang 23, current isolated SDK headers/sources and retained external
dependencies/generated fixture configuration. Seven moved mDNS source paths
were mapped privately; existing host thread-safety warnings were demoted in
the private build recipe. Final manifests bind sources and executables. This
is scoped native qualification, not full SDK GN regeneration, hosted CI, or
physical commissioning. The helper uses its real imported module and a freshly
compiled native payload library; no AST-only replacement proves the result.
